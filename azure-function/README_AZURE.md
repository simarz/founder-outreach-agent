# Running the Agent on Azure (Functions)

This folder is a self-contained **Azure Functions** app that runs the Founder
Follow-up Agent in the cloud on a daily timer — so it works with your computer
**off**. It stays within the Azure free grant (the timer runs for a few seconds
a day), so it costs essentially nothing on your Student credit.

## How it differs from the local version

| Concern | Local | Azure |
|---|---|---|
| Schedule | Windows Task Scheduler | Timer trigger (`0 0 8 * * *`) |
| Gmail token | `token.json` file | `GMAIL_TOKEN_JSON` app setting |
| Overrides + history | `contacts.csv`, `tracking.db` | Azure **Blob Storage** (`contacts.csv`, `tracking.json`) |
| Manual run | `python main.py` | `run-now` HTTP endpoint |

The scanning + reply logic (`tracker.py`, `notifier.py`) is identical to the
local version.

---

## Prerequisites

1. **Finish the local setup first** (see `../README.md`). You need a working
   `token.json` — generated by running `main.py` locally once. Azure reuses that
   token; there's no browser flow in the cloud.

2. **Publish the Google OAuth app.** In Google Cloud Console → OAuth consent
   screen → **Publish App**. While it's in "Testing", refresh tokens expire after
   7 days and the cloud job would stop working. Publishing keeps it alive.

3. **Install the tools** (one time):
   ```powershell
   winget install Microsoft.AzureCLI
   winget install Microsoft.Azure.FunctionsCoreTools
   az login
   ```

## Deploy (automated)

From this `azure-function` folder:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy.ps1
```

This creates a resource group, storage account, and Python Function App; loads
your token + settings as app settings; and publishes the code. It prints the
Function App name and the `run-now` URL when finished.

> The script reads `../token.json` for the `GMAIL_TOKEN_JSON` secret. Edit the
> variables at the top of `deploy.ps1` (notify email, time zone, region) before
> running if you want.

---

## Deploy (manual, if you prefer)

```powershell
# 1. Create resources
az group create -n founder-followup-rg -l eastus
az storage account create -n followupst<unique> -g founder-followup-rg -l eastus --sku Standard_LRS
az functionapp create -n founder-followup-<unique> -g founder-followup-rg `
  --storage-account followupst<unique> --consumption-plan-location eastus `
  --runtime python --runtime-version 3.11 --functions-version 4 --os-type Linux

# 2. Settings + secrets (GMAIL_TOKEN_JSON = the full contents of token.json)
az functionapp config appsettings set -n founder-followup-<unique> -g founder-followup-rg --settings `
  "NOTIFY_EMAIL=your-email@example.com" "LABEL_NAME=founders" "FOLLOWUP_DAYS=7" `
  "STATE_CONTAINER=followup-state" "WEBSITE_TIME_ZONE=Eastern Standard Time" `
  "GMAIL_TOKEN_JSON=$(Get-Content ..\token.json -Raw)"

# 3. Publish
func azure functionapp publish founder-followup-<unique> --python
```

## Test it

```powershell
# Stream logs while you trigger a run
func azure functionapp logstream founder-followup-<unique>
```

Get the `run-now` function URL + key from the Azure Portal (Function App →
Functions → run_now → Get Function URL), then open it in a browser or:

```powershell
curl "https://founder-followup-<unique>.azurewebsites.net/api/run-now?code=<function-key>"
```

It returns a one-line summary (threads scanned, follow-ups due, whether a digest
was emailed) and, if anyone is overdue, you'll receive the digest email.

## Day-to-day

- **Timer:** fires daily at 8 AM in the `WEBSITE_TIME_ZONE` you set (default
  Eastern). Change the schedule in `function_app.py` (`schedule="0 0 8 * * *"`,
  NCRONTAB = `sec min hour day month day-of-week`) and re-publish.
- **Edit names/companies:** the override file lives in Blob Storage as
  `contacts.csv` (container `followup-state`). Download it in the Azure Portal
  (Storage account → Containers) or with Azure Storage Explorer, edit, re-upload.
- **Change settings:** update app settings in the Portal (Function App →
  Settings → Environment variables) — no redeploy needed.
- **Follow-up limit:** `MAX_FOLLOWUPS` (default `2`) controls how many unanswered
  follow-ups are sent before a thread is closed out and stops appearing in your
  reminders. The agent counts the emails you sent in each thread to detect this
  automatically — no manual labeling needed. A newly-closed thread is listed once
  in the digest under "Closed — no reply", then dropped.
- **Responded label / Replied category:** founders who engaged — an in-thread
  reply was detected, or you applied the label named in `RESPONDED_LABEL`
  (default `responded`; may be nested under founders as `founders/responded`) —
  move to the **Replied** category. They keep the same 7-day follow-up cadence
  (reminded whenever the conversation is quiet for `FOLLOWUP_DAYS`), are exempt
  from the `MAX_FOLLOWUPS` closure, and live on the sheet's **Replied** tab.
- **Google Sheets export:** set the `SHEET_ID` app setting to a Google Sheet ID
  (the long string in its URL between `/d/` and `/edit`) and the agent mirrors the
  full tracking table there on every run. Leave it blank to disable. This needs
  the Sheets OAuth scope, so `GMAIL_TOKEN_JSON` must be a token generated **after**
  adding the scope — re-run the local OAuth flow (`del token.json; python main.py`)
  and paste the new `token.json` into `GMAIL_TOKEN_JSON`.

## Cost

Consumption plan: first 1,000,000 executions and 400,000 GB-s per month are free.
A once-a-day, few-second run is far under that. The storage account holds two tiny
blobs — pennies at most. Comfortably inside your Student credit.

## Security

- `GMAIL_TOKEN_JSON` is an app setting (encrypted at rest). For extra hardening
  you can move it to Azure Key Vault and reference it — optional.
- The agent only reads your mail and sends the digest to you. It never deletes or
  edits messages.
- The `run-now` endpoint requires the function key, so it isn't publicly callable
  without it.
